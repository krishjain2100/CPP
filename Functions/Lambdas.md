Introduced in C++11, a lambda expression is a convenient way to define an anonymous function object right at the location where it is invoked or passed as an argument.

When you write a lambda, the C++ compiler automatically generates an unnamed, hidden class (called a "closure type") that overloads the `operator()`.

### 1. The Anatomy of a Lambda

The general syntax looks like this:

`[captures] (parameters) -> return_type { body }`

- **`[captures]`**: The variables from the surrounding scope that the lambda is allowed to see and use. (This is the most critical part).

- **`(parameters)`**: Exactly like a normal function (e.g., `(int a, float b)`). You can omit the parentheses entirely if there are no parameters.

- **`-> return_type`**: The trailing return type. In 99% of cases, you can omit this, and the compiler will automatically deduce the return type based on your `return` statement.

- **`{ body }`**: The actual code to execute.

---
### 2. The Capture Clause (The Environment)

By default, a lambda cannot see any local variables outside of its own `{ body }`. You must explicitly tell it how to capture them.

- **`[]` (Empty):** Captures nothing. The lambda can only use global variables or variables passed as parameters.

- **`[x, y]` (Capture by Value):** The lambda makes a **copy** of `x` and `y`. Changes made inside the lambda do not affect the original variables.

- **`[&x, &y]` (Capture by Reference):** The lambda takes a **reference** to `x` and `y`. Changes inside the lambda _will_ modify the original variables.

- **`[=]` (Default Capture by Value):** The compiler automatically copies _any_ local variable you mention inside the lambda body.

- **`[&]` (Default Capture by Reference):** The compiler automatically references _any_ local variable you mention inside the lambda body.


_Note: You can mix them. `[=, &x]` means "copy everything I use, except `x`, which I want by reference."_

---
### 3. The `mutable` Keyword

If you capture a variable by value (`[x]`), the hidden class generated by the compiler makes the `operator()` method `const`. This means the copy of `x` is strictly read-only.


```cpp
int x = 5;
auto myLambda = [x]() {
    x = x + 1; // COMPILE ERROR: x is read-only
};
```

To modify a by-value capture, you must add `mutable`. This tells the compiler to remove the `const` qualifier, allowing the lambda to modify its own internal, private copies of the variables.


```cpp
int x = 5;
auto myLambda = [x]() mutable {
    x = x + 1; // SUCCESS. Internal copy is now 6. 
};
myLambda();
// Original 'x' in the main scope is STILL 5.
```

---
### 4.Init-Captures (C++-14)

Before C++14, you could only capture variables that already existed. With C++14 "Init-Captures" (or Generalised Captures), you can declare new variables directly inside the capture clause.

It is essential for moving move-only objects (like `std::unique_ptr` or `std::promise`) into a lambda, because you cannot copy them.


```cpp
std::unique_ptr<int> ptr = std::make_unique<int>(10);

// We create a new variable 'p' inside the lambda and MOVE 'ptr' into it.
auto myLambda = [p = std::move(ptr)]() { // an implicit auto type for p is used
    std::cout << *p << "\n";
};
```

---
### 5. Generic Lambdas (C++14 & C++20)

In C++14, lambdas gained the ability to use `auto` in their parameter lists, effectively turning the hidden closure class into a template.


```cpp
// C++14 Generic Lambda
auto printAnything = [](auto input) {
    std::cout << input << "\n";
};

printAnything(5);       // Instantiates with int
printAnything("Hello"); // Instantiates with const char*
```

In C++20, this was expanded to allow explicit template parameters on lambdas, giving you strict control over the types (e.g., forcing two parameters to be the exact same type).

```cpp
// C++20 Template Lambda
auto addSameType = []<typename T>(T a, T b) {
    return a + b;
};
```
