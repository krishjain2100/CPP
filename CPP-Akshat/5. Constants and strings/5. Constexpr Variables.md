### The `constexpr` keyword
- A **constexpr** variable is always a compile-time constant. As a result, a constexpr variable must be initialized with a constant expression, otherwise a compilation error will result.
- This functionality was not provided by const as there the variable might not be compile time constant.(and checking if it is compile-time constant could be tedious work sometimes,  here we directly get a warning)
- `constexpr` works for variables with non-integral types
- Constexpr variables are implicitly const. Const variables are not implicitly constexpr (except for const integral variables with a constant expression initializer).
- We can also do `constexpr const int myNum = 5;` but its redundant as `constexpr` is not part of an object's type, a variable defined as `constexpr int` actually has type `const int`.
-  We will discuss some types that are not fully compatible with `constexpr` (including `std::string`, `std::vector`, and other types that use dynamic memory allocation). For constant objects of these types, either use `const`, or pick a different type that is constexpr compatible (e.g. `std::string_view` or `std::array`).

#### Point to note
In C and C++, the declaration of an array object (an object can hold multiple values) requires the length of the array (the number of values that it can hold) be known at compile-time (so the compiler can ensure the correct amount of memory is allocated for array objects).
The C++ language standard added an exemption so that const integral types with a constant expression initializer would be treated as values known at compile-time, and thus be usable as array lengths
Now you might think we have been creating arrays with variable length all along:
That is just a backward compatible feature, In 1999, the C language introduced "Variable Length Arrays" (VLAs)
**Why does C++ ban them?**
If you use a VLA, it forces the variable-sized array onto the Stack (the small, fast memory).
If you create a large array, your program will instantly suffer a catastrophic crash known as a **Stack Overflow** and remember the stack is very tiny, your entire program is only given about **1 Megabyte** of Stack memory to work with.


Normal function calls are evaluated at runtime, with the supplied arguments being used to initialize the function’s parameters. Because the initialization of function parameters happens at runtime, this leads to two consequences:
1. `const` function parameters are treated as runtime constants (even when the supplied argument is a compile-time constant).
2. Function parameters cannot be declared as `constexpr`, since their initialization value isn’t determined until runtime.

### A brief introduction to constexpr functions
A **constexpr function** is a function that can be called in a constant expression. A constexpr function must evaluate at compile-time when the constant expression it is part of must evaluate at compile time (e.g. in the initializer of a constexpr variable). Otherwise, a constexpr function may be evaluated at either compile-time (if eligible) or runtime. To be eligible for compile-time execution, all arguments must be constant expressions.
