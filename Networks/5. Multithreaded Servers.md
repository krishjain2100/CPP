
Right now, your `epoll` (or `kqueue`) server is confined to a single physical CPU core at a time.
But the moment you introduce multiple threads to networking, you introduce race conditions.

---
### The Thundering Herd Problem

The most common mistake s trying to scale an `epoll` server by simply creating 4 threads and putting the exact same `epoll_wait()` loop inside all of them.

1. You have 1 `epoll` watchlist.

2. You have 4 threads all sleeping on `epoll_wait()`, watching the same Receptionist socket.

3. A single client sends a TCP `SYN` packet.

4. The OS Kernel receives the packet and says, _"Hey, FD 105 has data and is monitored by `epoll_fd 4`.!"_  So, the Kernel wakes up **all 4 threads**, that are waiting on this epoll's wait call, at the exact same microsecond.

5. All 4 threads sprint to call `accept()`.

6. Thread 1 wins the race, gets the new Client FD, and moves on.

7. Threads 2, 3, and 4 slam into an empty Accept Queue, fail, and are put back to sleep.


This is called the **Thundering Herd Problem**. It causes a massive Context Switch Storm inside the CPU. Waking up and putting a thread back to sleep is computationally expensive. 

To safely utilise all CPU cores, we have to use specific architectural patterns.

---
### Architecture 1: The Acceptor-Worker Pattern

You strictly separate the responsibility of _accepting_ connections from the responsibility of _processing_ data.

**1. The Main Thread (The Acceptor)**

- The Main Thread owns the Receptionist socket and its own private `epoll` watchlist.

- Its _only_ job is to sleep on `epoll_wait()`, wake up, call `accept()`, and get a new Client FD.

- It does NOT read data. Instead, it instantly hands that new Client FD to a Thread-Safe Queue and goes right back to listening for new users.


**2. The Thread Pool (The Workers)**

- You pre-spawn exactly as many Worker Threads as you have CPU cores (e.g., 8 threads).

- Each Worker Thread has its own private `epoll` watchlist (i..e., it's own RB Tree)

- When the Acceptor pushes a new Client FD into the queue, one Worker pulls it out, sets it to `O_NONBLOCK`, and adds it to its _own_ `epoll` instance. So now, every FD is present with exactly one `epoll` instance  and only this thread is woken up.

- The Workers are the ones who handle the `recv()`, the business logic, and the `send()`.

**The Result:** No Thundering Herd. Only one thread watches the Receptionist. The load is evenly distributed among the workers.

---
### Architecture 2: One-Loop-Per-Thread 

This is the architecture used by high-performance engines like **Nginx** and **Node.js**. Instead of a central Acceptor handing out work, we create independent, autonomous threads.

1. You spawn 8 threads.
2. Every single thread creates its _own_ Receptionist socket.
3. Every single thread creates its _own_ `epoll` watchlist.
4. Every single thread loops independently.

How can 8 different threads all call `bind()` on Port 8080? Historically, the OS Kernel would throw an `Address already in use` error and crash.

**(`SO_REUSEPORT`):** Modern OS kernels (Linux 3.9+ and newer macOS) introduced a socket flag called `SO_REUSEPORT`. If you apply this flag to your Receptionist sockets _before_ you bind them, the OS Kernel allows all 8 threads to bind to Port 8080 simultaneously.

The OS Kernel itself now acts as a hardware-level load balancer. When a `SYN` packet arrives at Port 8080, the Kernel hashes the IP address and deterministically hands the connection to exactly **one** of the 8 threads. The other 7 threads stay perfectly asleep.

---
### `EPOLLONESHOT`

If you design a system where multiple threads _might_ touch the same Client FD, you have to protect yourself against **Data Interleaving**.

Imagine Thread A wakes up because Client #1 sent 1,000 bytes. 
Thread A starts reading the data and parsing the JSON. But before Thread A finishes, Client #1 sends another 500 bytes.
If Thread B is idle, `epoll` might wake Thread B up to read the new 500 bytes. 
Now you have two threads reading different halves of the exact same client's message, completely corrupting your application's state.

To prevent this, you tell the Kernel to use **`EPOLLONESHOT`** when adding a client to the watchlist.

- **The Meaning:** _"Wake up exactly ONE thread when this socket has data. Then, immediately MUTE this socket in the watchlist."_ This ensures that no other thread gets woken up even if new data arrives.

- Thread A now has mathematically enforced monopoly over Client #1's File Descriptor. Thread A can call `recv()`, parse some JSON, realise it needs more data, loop around, and call `recv()` again to grab those extra 500 bytes out of the buffer. It can do this completely lock-free, running at maximum CPU speed, knowing with absolute certainty that no other thread is secretly stealing its data.

- If Thread A finishes processing Client #1, and just goes back to sleep on `epoll_wait()` without re-arming the socket, Client #1 is permanently stranded. If Client #1 sends a new request, the data goes into the buffer, but the alarm bell is still unplugged. Your server will just ignore them forever.

- So, before Thread A is allowed to abandon Client #1 and go handle someone else, it must manually call `epoll_ctl` with the `EPOLL_CTL_MOD` (Modify) command to explicitly plug the alarm bell back in.

---

Nginx uses One-Loop-Per-Thread, while Redis and Memcached lean toward Acceptor-Worker variations.

### The Acceptor-Worker

```cpp
#include <iostream>
#include <sys/epoll.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <unistd.h>
#include <fcntl.h>
#include <thread>
#include <vector>
#include <queue>
#include <mutex>
#include <condition_variable>

// --- The Thread-Safe Queue ---
std::queue<int> client_queue;
std::mutex queue_mutex;
std::condition_variable cv;

void make_non_blocking(int fd) {
    fcntl(fd, F_SETFL, fcntl(fd, F_GETFL, 0) | O_NONBLOCK);
}

// --- The Worker Silo ---
void worker_thread_logic(int worker_id) {
    // 1. Every worker gets its own PRIVATE watchlist
    int private_epoll_fd = epoll_create1(0);
    struct epoll_event events[10];

    while (true) {
        int new_client_fd = -1;

        // 2. Safely grab a new client from the Acceptor (The Lock)
        {
            std::unique_lock<std::mutex> lock(queue_mutex);
            // Sleep if the queue is empty. Wake up when cv.notify_one() is 
            // called.
            cv.wait(lock, [] { return !client_queue.empty(); });
            
            new_client_fd = client_queue.front();
            client_queue.pop();
        }

        // 3. Add the client to this worker's private watchlist
        make_non_blocking(new_client_fd);
        
        struct epoll_event event;
        event.events = EPOLLIN; 
        event.data.fd = new_client_fd;
        epoll_ctl(private_epoll_fd, EPOLL_CTL_ADD, new_client_fd, &event);

        std::cout << "Worker " << worker_id << " took FD " << new_client_fd << "\n";

        // 4. The Worker's Private Event Loop
        // Timeout is set to 10ms so the worker can occasionally loop back 
        // up and check the queue for new clients.
        int ready = epoll_wait(private_epoll_fd, events, 10, 10); 
        
        for (int i = 0; i < ready; i++) {
            char buffer[1024] = {0};
            int active_fd = events[i].data.fd;
            ssize_t bytes = recv(active_fd, buffer, sizeof(buffer), 0);

            if (bytes > 0) {
                // Read and Echo! 
                send(active_fd, buffer, bytes, 0);
                
            } else {
                // Client disconnected or an error occurred. 
                // closing the FD automatically removes it from the epoll
                // watchlist.
                close(active_fd); 
                std::cout << "Client on FD " << active_fd << " disconnected.\n";
            }
        }
    }
}

int main() {
    // 1. Setup the standard Receptionist (Main Thread only)
    int server_fd = socket(AF_INET, SOCK_STREAM, 0);
    struct sockaddr_in server_addr = { 
	    .sin_family = AF_INET, 
	    .sin_port = htons(8080), 
	    .sin_addr = {INADDR_ANY} 
	};
    bind(server_fd, (struct sockaddr*)&server_addr, sizeof(server_addr));
    listen(server_fd, 10);

    // 2. Boot up 4 Worker Threads
    std::vector<std::thread> workers;
    for (int i = 0; i < 4; i++) {
        workers.emplace_back(worker_thread_logic, i);
    }

    std::cout << "Acceptor Thread listening on 8080...\n";

    // 3. The Acceptor Loop (Blocking is fine because this thread ONLY accepts)
    while (true) {
        int client_fd = accept(server_fd, nullptr, nullptr);
        if (client_fd != -1) {
            // Push to queue and ring the bell to wake up EXACTLY ONE worker
            std::lock_guard<std::mutex> lock(queue_mutex);
            client_queue.push(client_fd);
            cv.notify_one(); 
        }
    }

    return 0;
}
```

### One-Loop-Per-Thread


```cpp
#include <iostream>
#include <sys/epoll.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <unistd.h>
#include <fcntl.h>
#include <thread>
#include <vector>

void make_non_blocking(int fd) {
    fcntl(fd, F_SETFL, fcntl(fd, F_GETFL, 0) | O_NONBLOCK);
}

void independent_silo_logic(int silo_id) {
    // 1. EVERY thread creates its own Receptionist socket
    int server_fd = socket(AF_INET, SOCK_STREAM, 0);

    // 2. THE MAGIC FLAG: Tell the OS to allow multiple bindings to 8080
    int opt = 1;
    setsockopt(server_fd, SOL_SOCKET, SO_REUSEPORT, &opt, sizeof(opt));

    // 3. Bind and Listen (All threads bind to the exact same port!)
    struct sockaddr_in server_addr = { 
	    .sin_family = AF_INET, 
	    .sin_port = htons(8080), 
	    .sin_addr = {INADDR_ANY} 
    };
    
    bind(server_fd, (struct sockaddr*)&server_addr, sizeof(server_addr));
    listen(server_fd, 10);
    make_non_blocking(server_fd);

    // 4. Create the private watchlist
    int epoll_fd = epoll_create1(0);
    struct epoll_event event;
    event.events = EPOLLIN;
    event.data.fd = server_fd;
    epoll_ctl(epoll_fd, EPOLL_CTL_ADD, server_fd, &event);

    struct epoll_event events[10];
    
    std::cout << "Silo " << silo_id << " successfully bound to Port 8080!\n";

    // 5. The Standard Event Loop (Identical to your single-threaded code)
    while (true) {
        int ready = epoll_wait(epoll_fd, events, 10, -1);

        for (int i = 0; i < ready; i++) {
            if (events[i].data.fd == server_fd) {
                // The OS Kernel's internal load balancer decided to hand this 
                // specific connection to THIS thread.
                int client_fd = accept(server_fd, nullptr, nullptr);
                make_non_blocking(client_fd);
                
                struct epoll_event client_event;
                client_event.events = EPOLLIN; 
                client_event.data.fd = client_fd;
                epoll_ctl(epoll_fd, EPOLL_CTL_ADD, client_fd, &client_event);
                
            } else {
                int active_fd = events[i].data.fd;
                char buffer[1024] = {0};
                ssize_t bytes = recv(active_fd, buffer, sizeof(buffer), 0);

                if (bytes > 0) {
                    send(active_fd, buffer, bytes, 0);
                } else {
                    close(active_fd);
                }
            }
        }
    }
}

int main() {
    // The main thread literally does nothing but spawn the Silos and wait.
    std::vector<std::thread> silos;
    
    for (int i = 0; i < 4; i++) {
        silos.emplace_back(independent_silo_logic, i);
    }

    // Keep the main thread alive while the Silos run in the background
    for (auto& silo : silos) {
        silo.join();
    }

    return 0;
}
```
