### Why do we need these libraries?

Until now we wrote raw POSIX C code.
We called `epoll_wait()`, and managed the `struct epoll_event` arrays manually.
This code would compile on Linux machines but not on a MacBook because

- Linux uses `epoll`, while
- macOS uses `kqueue`.
- Windows uses `I/O Completion Ports (IOCP)`.

Writing an `#ifdef LINUX` block for every single OS networking API is not feasible

To solve this, Wrapper Libraries are built. 
These libraries sit directly on top of the OS Kernel. 
You write a generic C/C++ code, and the library automatically translates it into `epoll`, `kqueue`, or `IOCP` behind the scenes.

There are 3 major ones:

---
### 1. `libuv`: The Engine Behind Node.js

Node.js is famous for being Asynchronous and Non-Blocking.
But JavaScript doesn't actually know how to talk to a network card or a hard drive.
Underneath Node.js is a massive, highly optimised C library called **`libuv`**.

- **The Architecture:** `libuv` implements the **Reactor Pattern**(it tells us that data is ready, but we have to go read it ourselves). It contains a master Event Loop that wraps `epoll`/`kqueue`.

- **The Thread Pool:** `epoll` is great for network sockets, but on Linux, you _cannot_ use `epoll` for local hard drive files. Disk I/O is always blocking. To prevent a file read from freezing the network server, `libuv` spins up a hidden C thread pool in the background. If you ask `libuv` to read a file, it ships that task to a background thread, while the main thread keeps reading network packets.

---
### 2. `Boost.Asio`: The C++ Standard

If you are writing a modern, high-performance C++ backend, you will almost certainly use `Boost.Asio`. It is so fundamental that it is currently the basis for the official standard C++ Networking Technical Specification.

- **The Architecture:** Unlike `libuv`, `Boost.Asio` uses the **Proactor Pattern**.
- **Reactor (`epoll`) vs. Proactor (`Asio`):** 
	* A **Reactor** tells you: _"Data is ready! Go read it yourself."_
	* A **Proactor** tells you: _"I read the data for you in the bg. Here is the populated buffer."_ 

`Boost.Asio` achieves this asynchronous magic using modern C++ features like lambda functions, `std::future`, and C++20 coroutines, completely hiding the kernel-level byte-copying from you.

---
### 3. ZeroMQ (ZMQ): The Distributed Router

`libuv` and `Asio` are brilliant for connecting a Client to a Server. But what if you have a microservices architecture? What if Server A needs to blast messages to Servers B, C, and D?

>A **Microservices Architecture** is a distributed systems design pattern where a single application is built as a collection of small, loosely coupled, and independently deployable backend services. Instead of compiling all your code into one massive program, you split the application into isolated pieces based on **business capabilities** (e.g., one service handles User Logins, another handles Payments, another handles Inventory). So these servers have to communicate to each other through the network, mostly using TCP.

Managing raw TCP sockets, reconnection logic for 50 different microservices is a nightmare. 
**ZeroMQ** is a C++ library that makes networking look like standard multithreading.

**The Architecture:** ZMQ completely hides the concept of Sockets and File Descriptors. Instead, it gives you distributed patterns. [[10. ZMQ]]
