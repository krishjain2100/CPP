
### 1. Semaphores (`std::counting_semaphore` & `std::binary_semaphore`)

A Semaphore bridges the gap is a **resource counter** that limits how many threads can access a critical section simultaneously.  If the capacity is 3, three threads can enter. The fourth thread is blocked at the door until someone leaves.


```cpp
#include <semaphore>
#include <thread>

// Allow a maximum of 3 threads inside simultaneously
std::counting_semaphore<3> pool_slots(3);

void accessResource() {
    pool_slots.acquire(); // Decrements counter. If 0, blocks thread.
    
    // Critical Section (Max 3 threads here at once)
    
    pool_slots.release(); // Increments counter. Wakes up waiting thread.
}
```

- **`std::binary_semaphore`** is just an alias for `std::counting_semaphore<1>`. It can be used like a mutex, but unlike a mutex, **any thread can unlock a semaphore**, whereas only the thread that _locked_ a mutex is allowed to unlock it.

### 2. Synchronisation Barriers (`std::latch` & `std::barrier`) 

These are used when you have multiple threads working in parallel, and they all need to wait for each other to reach a specific checkpoint before anyone is allowed to proceed.

#### A. `std::latch`

A latch is initializsed with a counter. Threads count it down. Once it hits zero, the gate opens forever.
**Use case:** Waiting for 5 distinct plugins to finish initialization before starting the main loop.

```cpp
#include <latch>

std::latch startup_barrier(5); // Wait for 5 threads

void initTask() {
    // Perform setup...
    startup_barrier.count_down(); // Decrement without blocking
}

int main() {
    // Spawn 5 threads...
    startup_barrier.wait(); // Main blocks here until counter hits 0
}
```

#### B. `std::barrier`

Unlike a latch, a barrier resets its counter once it hits zero. It locks threads at a gate, drops the gate when everyone arrives, executes an optional completion function, and then resets for the next loop phase.

Game engines or graphics pipelines where 4 threads calculate physics frames, must all finish Frame 1 together, then loop to calculate Frame 2.


```cpp
#include <barrier>

// 4 threads sync. When all arrive, run the lambda.
std::barrier physics_gate(4, []() noexcept { 
    std::cout << "All threads finished current frame. Advancing time!\n"; 
});

void workerLoop() {
    while(true) {
        // Calculate physics step...
        physics_gate.arrive_and_wait(); 
        // Block until all 4 arrive, then reset loop.
    }
}
```

### 3. Broadcasting Results (`std::shared_future` & `std::packaged_task`)

Recall, `std::future::get()` can only be called **once**; after that, the future is emptied and a second call crashes.

What if 10 worker threads are all waiting for a single background initialisation thread to deliver a configuration object? You need to broadcast the result to multiple receivers.

#### `std::shared_future<T>`

You can convert a standard `std::future` into a `std::shared_future` using `.share()`. This object can be copied infinitely, and multiple threads can call `.get()` safely on their own copies.


```cpp
#include <future>

std::promise<int> config_prom;
std::shared_future<int> config_fut = config_prom.get_future().share(); // Convert to shared

void workerThread(std::shared_future<int> fut) {
    int val = fut.get(); // Multiple threads can call this! It blocks until ready, but doesn't empty.
}
```

#### `std::packaged_task<Signature>`

A wrapper that connects a standard C++ function directly to a future. It handles creating the promise and catching exceptions automatically. It is the foundation for building your own Custom Thread Pools.


```cpp
#include <future>

// Wraps a function that takes an int and returns an int
std::packaged_task<int(int)> task([](int x) { return x * 2; });
std::future<int> result = task.get_future(); // Get the receipt

task(10); // Run the task (manually or hand it to a thread)
int final_val = result.get(); // Returns 20
```

### 4. Parallel Algorithms (`std::execution`)

 C++17 overhauled the Standard Template Library (STL) algorithms (`std::sort`, `std::transform`, `std::find_if`) to run concurrently across multiple CPU cores automatically using **Execution Policies**.


```cpp
#include <algorithm>
#include <vector>
#include <execution> // Required header

std::vector<int> vec = { /* 10 million elements */ };

// Standard sequence sort (Single-threaded)
std::sort(vec.begin(), vec.end());

// FREE PARALLELISM: The OS splits the vector across your CPU cores 
// and compiles a highly optimized parallel sort automatically.
std::sort(std::execution::par, vec.begin(), vec.end());
```

- **`std::execution::par`**: Multi-threaded parallel execution.
- **`std::execution::par_unseq`**: Parallelised _and_ Vectorised (utilises CPU SIMD hardware instructions for maximum speed).

### 5. False Sharing (Cache Line Bouncing)

 Lock-free atomic code can slow down drastically due to a physical hardware limitation called **False Sharing**.

The CPU does not read individual bytes from RAM; it reads memory in chunks called **Cache Lines** (typically 64 bytes).

Imagine you have a struct containing two completely separate atomic variables:

```cpp
struct CoreCounters {
    std::atomic<int> threadA_count; // 4 bytes
    std::atomic<int> threadB_count; // 4 bytes
}; // Both sit on the exact same 64-byte Cache Line in hardware!
```

If CPU Core 1 modifies `threadA_count` and CPU Core 2 simultaneously modifies `threadB_count`, they do not interfere at a software level. But at a _hardware architecture_ level, whenever Core 1 writes to its variable, it forces the entire 64-byte cache line to become invalid on Core 2's cache. Core 2 is forced to halt, reload the memory from shared RAM, update its variable, which then invalidates Core 1's cache.

The data bounces back and forth between CPU caches affecting performance

#### The Fix: Hardware Alignment

You must force variables used by different threads to live on completely separate cache lines using `alignas`:

```cpp
#include <new> // For destructive interference sizes

struct CoreCounters {
    // Force these variables to be separated by at least one full cache line width
    alignas(std::hardware_destructive_interference_size) std::atomic<int> threadA_count;
    alignas(std::hardware_destructive_interference_size) std::atomic<int> threadB_count;
};
```
