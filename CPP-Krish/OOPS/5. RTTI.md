Run-time type information (RTTI) is a feature of C++ that exposes information about an object’s data type at runtime. This capability is leveraged by dynamic_cast. 
Normally, C++ is a statically typed language. The compiler knows exactly what every variable is (an `int`, a `Car*`, a `Shape*`) before you run the code.
However, when using **Polymorphism**, you often lose this specific information. You might have a `std::vector<Animal*>` that contains `Dog*`, `Cat*`, and `Bird*`. But the compiler only sees `Animal*`.

RTTI only works for classes that have at least one virtual function.
- When the compiler creates the VTable for a class (which has atleast one virtual function), it adds an extra slot pointing to a `type_info` structure right above the function pointers in the VTable.
- This `type_info` struct contains the mangled name of the class (e.g., `"3Dog"`) and pointers to its Base classes' `type_info` structs. This creates a graph in your program's memory.

RTTI is used for `dyamic_cast` and `type_id`

#### `dynamic_cast`

The need for dynamic_cast:

```cpp
class Base {
protected:
	int m_value{};
public:
	Base(int value) : m_value{value} {}
	virtual ~Base() = default;
};

class Derived : public Base {
protected:
	std::string m_name{};
public:
	Derived(int value, std::string_view name) : Base{value}, m_name{name} { }
	const std::string& getName() const { return m_name; }
};

Base* getObject(bool returnDerived) {
	if (returnDerived) return new Derived{1, "Apple"};
	else return new Base{2};
}

int main() {
	Base* b{ getObject(true) };
	// how do we call Derived object's getName() here, with only a Base pointer?
	delete b;
}
```

One way would be to add a virtual function to Base called `getName()` and have it dynamically resolve to `Derived::getName()`.  But what would this function return if you called it with a Base pointer/reference that was actually pointing to a Base object ? Here's where `dynamic_cast` comes into play for down-casting.

It tries to convert a Base pointer to a Child pointer.
- If the object is that Child type, it returns the pointer.
- If the object is not that Child type, it returns `nullptr`.

```cpp
int main() {
	Base* b{ getObject(true) };
	Derived* d{ dynamic_cast<Derived*>(b) }; 
	if (d)  cout << "The name of the Derived is: " << d->getName() << '\n';
	delete b;
}
```

`dynamic_cast` can also be used with references. This works analogously to how it works with pointers. Because C++ does not have a null reference, it can’t return a null reference upon failure. Instead, if the `dynamic_cast` of a reference fails, an exception of type `std::bad_cast` is thrown.

Note that because `dynamic_cast `does some consistency checking at runtime (to ensure the conversion can be made), use of `dynamic_cast` does incur a performance penalty.

`dynamic_cast` fetches the `type_info` of `b` via vptr. If it's a match with that of `Derived` (casted to class) then it is safe and returns the pointer.  If it does not match then it walks up the inheritance tree. If it finds `Derived` along the way, it knows the cast is safe and returns the pointer. If it reaches the top of the tree without finding `Derived`, it returns `nullptr`.

Note that there are several cases where downcasting using` dynamic_cast` will not work:
1. With protected or private inheritance because the outside world is not allowed to know about this inheritance. So even `Base &b = d` is also not allowed outside the class scope for private inheritance. But C-style cast can convert a derived object to a base class that is inaccessible (e.g. because it was privately inherited). It just turns a blind eye to the access specifier during `static_cast` checking phase. Note that `static_cast` itself respects the specifiers.
2. For classes that do not declare or inherit any virtual functions (and thus don’t have a virtual table).
3. In certain cases involving virtual base classes (see [this page](https://msdn.microsoft.com/en-us/library/cby9kycs.aspx) for an example of some of these cases, and how to resolve them).

It turns out that downcasting can also be done with `static_cast`. But it is obviously dangerous.  If you’re absolutely sure that the pointer you’re downcasting will succeed, then using `static_cast` is acceptable. One way to ensure that you know what type of object you’re pointing to is to use a virtual function. Here’s one way to do that:

```cpp
enum class ClassID {
	base,
	derived
	// Others can be added here later
};

class Base {
protected:
	int m_value{};
public:
	Base(int value) : m_value{value} {}
	virtual ~Base() = default;
	virtual ClassID getClassID() const { return ClassID::base; }
};

class Derived : public Base {
protected:
	std::string m_name{};
public:
	Derived(int value, std::string_view name) : Base{value}, m_name{name} {}
	const std::string& getName() const { return m_name; }
	ClassID getClassID() const override { return ClassID::derived; }
};

Base* getObject(bool bReturnDerived) {
	if (bReturnDerived) return new Derived{1, "Apple"};
	else return new Base{2};
}

int main() {
	Base* b{ getObject(true) };
	if (b->getClassID() == ClassID::derived) {
		Derived* d{ static_cast<Derived*>(b) };
		cout << "The name of the Derived is: " << d->getName() << '\n';
	}
	delete b;
}
```

But if you’re going to go through all of the trouble to implement this (and pay the cost of calling a virtual function and processing the result), you might as well just use `dynamic_cast`.

In general, using a virtual function _should_ be preferred over downcasting. However, there are times when downcasting is the better choice:
- When you can not modify the base class to add a virtual function (e.g. because the base class is part of the standard library)
- When you need access to something that is derived-class specific (e.g. an access function that only exists in the derived class)
- When adding a virtual function to your base class doesn’t make sense (e.g. there is no appropriate value for the base class to return). Using a pure virtual function may be an option here if you don’t need to instantiate the base class.

#### `typeid` (Type Identification)

This allows you to compare types directly.
It compares the memory address of the two `type_info` structs.

```cpp
#include <typeinfo> // Required header
void checkType(Animal* ptr) {
    if (typeid(*ptr) == typeid(Dog)) {
        cout << "This is exactly a Dog.";
    }
    // You can also get the name (implementation dependent)
    cout << typeid(*ptr).name(); // Might print "class Dog" or "3Dog"
}
```

### The Cost of RTTI

It adds a small amount of data to every class (the `type_info` struct).
`dynamic_cast` is slow. It has to traverse the inheritance tree at runtime to check validity.
Because RTTI has a pretty significant space performance cost, some compilers allow you to turn RTTI off as an optimisation ((like `-fno-rtti` in GCC/Clang)). Needless to say, if you do this, dynamic_cast won’t function correctly.
