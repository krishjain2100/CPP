A **Virtual Machine (VM)** is a software-based emulation of a physical computer.

You can install a completely different Operating System (the Guest) inside this software container. The Guest OS operates under the illusion that it has its own dedicated physical hard drive, memory, and CPU.

In reality, a specialised piece of software called the **Hypervisor** sits beneath the Guest OS. The hypervisor acts as the ultimate resource manager. Whenever the Guest OS asks for CPU power, memory, or storage, the hypervisor intercepts that request and securely allocates a slice of the actual **physical hardware** to full-fill it, keeping the VM completely isolated from anything else running on the machine.

### 1. Categorization

There are two types of VMs depending on where the hypervisor is installed"
#### Type 1: The Bare Metal Hypervisor

- **How it works:** The hypervisor is installed _directly_ onto the blank physical hardware of the server. There is no Host Operating System (no Windows, no macOS). The hypervisor itself essentially acts as a highly specialized, stripped-down OS whose only job is to run VMs.
    
- **Why use it:(Over Type 2)** Maximum performance and lowest latency. Because there is no Host OS getting in the way, the VMs interact almost directly with the hardware. This is what powers massive data centers, cloud providers (AWS, Google Cloud), and high-performance enterprise servers. _(Examples: VMware ESXi, Microsoft Hyper-V, Proxmox)._
	
- **Main purpose**: We can run many vm's parallely on a single machine as compared to a normal OS. The Hypervisor basically works as a hardware power distributor between the different vm's installed on the machine
#### Type 2: The Hosted Hypervisor

- **How it works:** You install a normal Host Operating System first (like macOS or Windows on your laptop). Then, you install the hypervisor as a regular software application on top of that Host OS.
    
- **Why use it:** Convenience. You use this when you want to keep using your personal laptop's main OS to browse the web and write code, but you occasionally need to spin up a Linux environment to test a script or run a specific application. It has more overhead (because the Host OS uses up resources too), but it is incredibly easy to set up. _(Examples: VirtualBox, VMware Workstation, Parallels)._
