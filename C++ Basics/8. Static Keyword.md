### 1. Static keyword for Global Identifiers

Global variables/functions have external linkage by default. Adding `static` to a global variable gives it internal linkage.

---
### 2. Static keyword for Local Variables

Local variables have automatic duration by default, which means they are created at the point of definition, and destroyed when the block is exited. `static` keyword on a local variable changes its duration from automatic to static. This means the variable is now created at the start of the program (the memory is reserved at the very beginning of the program, but the variable is initialised/reinitialised when the code encounters it for the first time), and destroyed at the end of the program (just like a global variable). As a result, the static variable will retain its value even after it goes out of scope.
 
```cpp
void counter() {
	static int count = 0; // Created ONCE. Skipped on future calls.
	count++;
	cout << count << endl;
} // 'count' is NOT destroyed. It sits in global data segment.

int main() {
	counter(); // Prints 1
	counter(); // Prints 2
	counter(); // Prints 3
}
```

- Static local variables that are zero-initialised or have a constexpr initialiser can be initialised at program start.
- Static local variables that have no initialiser or a non-constexpr initialiser are zero-initialised at program start.
- Static local variables with a non-constexpr initialiser are reinitialised the first time the variable definition is encountered. The definition is skipped on subsequent calls, so no futher reinitialisation happens.

**Static local constants**
Static local variables can be made const (or constexpr). One good use for a const static local variable is when you have a function that needs to use a const value, but creating or initialising the object is expensive. If you used a normal local variable, the variable would be created and initialised every time the function was executed. With a const/constexpr static local variable, you can create and initialise the expensive object once, and then reuse it whenever the function is called.

**Don't use static local variables to alter flow**.
Someone looking at the name of the function wouldn't be able to guess that it does not run the same every time.

```cpp
int getInteger() {
	static bool s_isFirstCall{ true };
	if (s_isFirstCall) {
		cout << "Enter an integer: ";
		s_isFirstCall = false;
	} else {
		cout << "Enter another integer: ";
	}
	int i{};
	cin >> i;
	return i;
}
```

### 3. Static Member Variables

When you put `static` on a member variable, it is no longer owned by the object. It is owned by the **Class itself**. All objects share **ONE** copy of static member variables. It has external linkage.
Essentially, static members are global variables that live inside the scope region of the class. 

Although you can access static members through objects of the class, static members exist even if no objects of the class have been instantiated. This makes sense: they are created at the start of the program and destroyed at the end of the program, so their lifetime is not bound to a class object like a normal member.

Because static member exists independently of any class objects, it can be accessed directly using the class name and the scope resolution operator.

Usually we only keep the declaration of the static member variable inside the class to keep the interface clean If you are defining a static member outside of the class, you are allowed to define and initialize private or protected members. This is because using the `ClassName::` prefix places the rest of the definition into the class's scope, granting you the same access privileges as the class itself. But you can't access private static member variable using  class name and scope resolution or through an object.

For non-template classes, if the class is defined in a header file, the static member definition is usually placed in the associated code file for the class. Alternatively, the member can also be defined as `inline` and placed below the class definition in the header (this is useful for header-only libraries). If the class is defined in a source (.cpp) file, the static member definition is usually placed directly underneath the class. Do not put the static member definition in a header file (much like a global variable, if that header file gets included more than once, you’ll end up with multiple definitions, which will cause a linker error). 

For template classes, the (templated) static member definition is typically placed directly underneath the template class definition in the header file (this doesn’t violate the ODR because such definitions are implicitly inline). **(DID NOT UNDERSTAND)**

There are a few shortcuts to the above:

- When the static member is a constant integral type (which includes `char` and `bool`) or a const enum, the static member can be initialized inside the class definition.
- Inline variables are allowed to have multiple definitions. C++17 allows static members to be inline variables. Such variables can be initialized inside the class definition regardless of whether they are constant or not. This is the preferred method of defining and initializing static members.
- Because `constexpr` members are implicitly inline (as of C++17), static `constexpr` members can also be initialized inside the class definition without explicit use of the `inline` keyword

----
#### Use-case

One use of static members  is to assign a unique ID to every instance of the class.

```cpp
class Something {
private:
    static inline int s_idGenerator { 1 };
    int m_id {};
public:
    Something() : m_id { s_idGenerator++ } {}
    int getID() const { return m_id; }
};

int main() {
    Something first{};
    Something second{};
    std::cout << first.getID() << '\n'; // 1 
    std::cout << second.getID() << '\n'; // 2 
}
```

Other is to store common const data for the class so that it is not copied over and over again for every object.

----
#### Type deduction (`auto` and CTAD)

A static member may use `auto` to deduce its type from the initializer, or Class Template Argument Deduction (CTAD) to deduce template type arguments from the initializer.
Non-static members may not use `auto` or CTAD.

The reasons for this distinction being made are quite complicated, but boil down to there being certain cases that can occur with non-static members that lead to ambiguity or non-intuitive results. This does not occur for static members. Thus non-static members are restricted from using these features, whereas static members are not.

```cpp
class Foo {
private:
    auto m_x { 5 };   // auto not allowed for non-static members
    std::pair m_v { 1, 2.3 }; // CTAD not allowed for non-static members
    static inline auto s_x { 5 };   // auto allowed for static members
    static inline std::pair s_v { 1, 2.3 }; // CTAD allowed for static members
};
```

### Static Member Functions

```cpp
class Something {
private:
    static inline int s_value { 1 };
public:
    int getValue() { return s_value; }
};

int main() {
    std::cout << Something::s_value; // does not work, private data
    Something s{};
    std::cout << s.getValue(); 
    // works, but requires us to instantiate an object to call getValue()
}
```

Now with a static member function accessor:

```cpp
#include <iostream>

class Something {
private:
    static inline int s_value { 1 };
public:
    static int getValue() { return s_value; } // static member function
};

int main() {
    std::cout << Something::getValue() << '\n';
}
```

Because static member functions are not associated with a particular object, they can be called directly by using the class name and the scope resolution operator (e.g. `Something::getValue()`). Like static member variables, they can also be called through objects of the class type, though this is not recommended.

Static member functions have two interesting quirks worth noting. 
First, because static member functions are not attached to an object, they have no `this` pointer. This makes sense, the `this` pointer always points to the object that the member function is working on. Static member functions do not work on an object, so the `this` pointer is not needed.

Second, static member functions can directly access other static members (variables or functions), but not non-static members. This is because non-static members must belong to a class object, and static member functions have no class object to work with.

Static member functions can also be defined outside of the class declaration. This works the same way as for normal member functions.

```cpp
class IDGenerator {
private:
    static inline int s_nextID { 1 };
public:
     static int getNextID(); // Here's the declaration for a static function
};
// Note we don't use the static keyword here (as the static here would make the compiler think to give this internal linkage, but you just used static inside the class to give it external linkage).
int IDGenerator::getNextID() { return s_nextID++; }
int main() {
    for (int count{ 0 }; count < 5; ++count)
        std::cout << "The next ID is: " << IDGenerator::getNextID() << '\n';
}
```

As noted earlier, member functions defined inside the class definition are implicitly inline. 
So static member functions can be defined inside without issues (but not preferred). 
Static member functions defined outside the class definition are not implicitly inline, but can be made inline by using the `inline` keyword.

### Pure static classes

Classes with all static members are called Pure Static Classes (also called "monostates").
Though there would be no point of having objects of this class.

Instead of writing a class with all static members, consider writing a normal class and instantiating a global instance of it (global variables have static duration). That way the global instance can be used when appropriate, but local instances can still be instantiated.

Pure static classes have a lot of overlap with namespaces. Both allow you to define variables with static duration and functions within their scope region. However, one significant difference is that classes have access controls while namespaces do not. In general, a static class is preferable when you have static data members and/or need access controls. Otherwise, prefer a namespace.

### C++ does not support static constructors

If you can initialize normal member variables via a constructor, then by extension it makes sense that you should be able to initialize static member variables via a static constructor. And while some modern languages do support static constructors for precisely this purpose, C++ is unfortunately not one of them.

If initializing your static member variable requires executing code (e.g. a loop), one way that works with all variables, static or not, is to use a function to create an object, fill it with data, and return it to the caller. This returned value can be copied into the object being initialized.

```cpp

struct Chars {
    char first{};
    char second{};
};
class MyClass {
private:
    static Chars generate() {
        Chars c{}; // create an object
        c.first = 'a'; // fill it with values however you like
        c.second = 'e';
        return c; // return the object
    }
public:
	static inline Chars s_mychars { generate() };
	 // A lambda can also be used for this.
};

int main() {
    std::cout << MyClass::s_mychars.second; // print e
}
```

Obviously `generate()` needs to be static because, `s_mychars` is intitalised even before `main()`runs, so there are no objects of the class and therefore no `this` pointer and member functions need their `this` pointer to run. Static Functions, on the other hand, are guaranteed to be pure logic. The compiler knows they will never try to touch object data, (non static members) so they are perfectly safe to run before any objects exist.
